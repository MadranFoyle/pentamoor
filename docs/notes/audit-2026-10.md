# Documentation audit, October 2026

A check of what the README, CONTRIBUTING, the documents in `docs/`, the release README and notice, and the workflows say, against the code and the CI as they were after the controller and D-pad navigation, the display and
full-screen work, the Steam Deck download, build profiles, the release archives and installer, the iPad proof of concept, message boxes, the Windows runtime, the Spells of the Ancients research and the removal of the upstream
decompilation material. What was wrong was corrected where the right answer could be read from the code or the CI; what could not be decided from the repository is listed here with file and line, for the maintainer.
Line numbers are those of the tree this audit was made on.

## What was checked, and held

- The README's **Controls** table against the bindings table at the top of `src/port/pad.c` (A, B, X, Y, Start, Back, LB, RB, LT, RT, both sticks, the D-pad), the 500 ms hold of Back on the title menu (`PAD_BACK_HOLD_MS`) and the 1 s L3 + R3 full-screen combination (`DISPLAY_COMBO_MS`, `front_sdl.c`).
  One control was missing from the table (L3 is Space) and is there now.
- The README's **Display** section against `display.h`, `display.c` and `display_cfg.c` (keys, the three scaling modes and filters and their defaults, the 90% rules, `display.cfg`'s keys and what the environment wins over, the window title).
- The install steps: `pentamoor`, `pentamoor-install`, `tools/install/install.py` and its options (`--build`, `--clean`, `--self-test`, `--check`, `--compiler`, `--no-download`), the `.iso` dropped on the launcher, exit status 3 for a build with no profile, `PORT_RES`'s default, `PORT_FRAME_MS`'s default.
- CONTRIBUTING's build, test and release instructions against the Makefile targets (`runtime`, `modules`, `static`, `test`, `check-*`, `ios-runtime`), `modbuild.py --list-targets`, the three workflows, and "Adding a build" against `profile.c`, `profile.h`, `tools/lift/builds.py` and `test_lift.py`.
- Every relative link of every Markdown file (the new `tools/release/check_links.py`; none was broken), and every backticked repository path in the Markdown and text files (a throwaway scan; the ones that name nothing are the removed `src/magic`, `src/winlayer` and `src/platform`, which the notes already call removed or planned, and build outputs).
- The tests and make targets that need no game: `make -C src/port test` (all green on the Mac the audit ran on), `pytest tools/install tools/lift tools/steamdeck tools/release tools/ios tools/research` (241 tests, then the new ones), `tools/difftest`, `tools/registry` and `tools/verification_harness/tests` (59 passed, 2 skipped), `check_tree.py`.

## How to read the older notes

- **Pull request numbers and commit ids** in the notes (`PR #107`, `#110 to #114`, `de0e03f`, `8e72475`) are those of the maintainer's earlier repository; this repository's history starts fresh (README, "History").
- **Decompiler names** (`FUN_004080b2`, `Duel_ChooseTarget`, `magic_all.c`, `Ai_Subsystem_004b42dc`) in `docs/` refer to the removed material; the addresses beside them are the executables' and are what to trust.
- **Coordinates** in the older notes are 640x480 unless they say otherwise (`overworld.md` says so at the top).
- **Counts of checks** ("70 checks", "45 checks", "41 now") are as of the day each was written; run `make -C src/port test` for today's.

## Open questions

These are things the repository cannot settle. None was changed.

### Legal and wording (not changed on purpose; decide, then edit)

1. **Hand-written C written "from the decompiled bodies".** Five files of `src/native` say so in their header comment (`card_query.c:5`, `ai_plan.c:13`, `card_util.c:6`, `card_scan.c:6`, `event_context.c:7`); `ai_eval.c:12` says "from the disassembly". The README's Legal section says
   the reimplemented functions were "written after studying the original's machine code (and, early on, a decompiler's reading of it)" (README.md:177-178). The two agree, but the comments are more specific than the README; the maintainer may want to decide whether the README should say so as plainly, or the comments be reworded.
2. **Names from a decompiler's tables in tracked files.** `docs/SYMBOL_VERIFICATION.md` (734 lines) and `tools/registry/verified_names.csv` list names, with addresses, that were first guessed by the decompiler and then checked against the running game; `tools/difftest/SPEC.md:78,164,207-216` and
   `tools/difftest/make_doc_vectors.py` carry decompiler-given names in their tables. README.md:176 says "no decompiler output ... and no table made from one" and `check_tree.py` passes. These are names *verified* by running the game, not output, but they are the closest thing in the tree to a "table made from" a decompiler; worth a deliberate yes.
3. **"The maintainer keeps a private copy outside the repository"** (README.md:189) is a statement only the maintainer can vouch for.
4. **No license.** README.md:181 ("The repository has no license file; do not redistribute game files") and `tools/release/NOTICE.txt:27` ("no licence file ... published for reading and for building from your own copy") are consistent with each other, but no license means no permission to copy or modify under the law of most places; the repository began as a fork of
   a project whose license (if any) was not checked here. `docs/PORT_STRATEGY.md` ("Risks") also notes Unicorn (GPL-2.0), which the emulator spike under `tools/emu_spike` uses and the native program does not.
5. The release archives and the GitHub release text say the Windows and macOS x86-64 builds "have only been built and unit tested by CI" (`.github/workflows/release.yml`, the notes it writes); true, and the README's table agrees. Nothing to change; listed because it is the claim most likely to be read as stronger than it is.

### Things the audit could not verify

6. README.md:145 (Linux "tested ... on CachyOS with gcc, but headless") and the timings in `docs/PHASE_C.md` ("Timings") are one machine's reports. The README's macOS "tested" has no detail at all.
7. README.md:16 and `README.release.txt`: the `mdf2iso "MTG v1.0.mdf" "MTG v1.0.iso"` conversion is advice; the installer rejects an `.mdf` (`tools/install/iso9660.py:42`) but nothing checks that `mdf2iso` output is accepted.
8. **F11 on a Mac.** The README names F11 first. On macOS the system's own F11 (Show Desktop, or the function-key setting) can take the key before the game sees it; Alt+Enter and L3 + R3 are the other ways. Not tried on a Mac with the default keyboard settings (`docs/notes/display.md` ran on a hidden window and an X server).
9. **Windows display scaling.** `front_sdl.c:1609` sets the per-monitor DPI hint, `display.md` lists it under "Not checked", and the README now says it has not been seen; `ROADMAP.md` agrees.
10. **The `controller_neptune_pentamoor.vdf` layout, the Steam shortcut writer, kdialog/zenity windows, Steam's keyboard** are listed under "Not verified" in `docs/notes/steamdeck.md` (items 3 to 6); the README says the same in one line. `tools/steamdeck/` has no README of its own (the task list for this audit named one); `steamdeck.md` is the documentation.
11. `docs/notes/ios.md` was written against Xcode 27.0, an iPad Pro 13-inch (M5) simulator and iOS 27.0; none of that was rerun. Its `sources/kits/make-ipad-kit.sh` (ios.md:21, `tools/ios/deploy.py:21`) is deliberately not in the repository.

### Code and tooling found stale while reading (not fixed: code, not documents)

12. `src/port/compare_screen.py:25` starts `src/port/build/pentamoor`, the single executable that only `make static` makes; `make -C src/port` makes `pentamoor-run` and the game modules, so the script stops with "needs the installed game and src/port/build/pentamoor". It also needs `sources/emu_overlay` and the emulator's `unicorn`.
    CONTRIBUTING.md and README.md quote its result (0 of 307,200 pixels differ); that number was measured when the executable existed.
13. `PORT_HEADLESS` is "set at all" for the window (`front_sdl.c:1592`, so `PORT_HEADLESS=0` is also headless) but "set and not 0" for the message-box choice (`msgbox.c:157-158`). CONTRIBUTING's table says so; one of the two should probably change.
14. `.github/workflows/ci.yml` names its actions by tag (`actions/checkout@v4` at lines 25 and 117, `actions/setup-python@v5` at 38 and 160, `msys2/setup-msys2@v2.32.0` at 119); `package.yml` and `release.yml` pin full commit SHAs, as CONTRIBUTING.md ("Making a release") asks. Pinning `ci.yml` too is a one-line-each change.
15. `docs/notes/castle-dungeon-stats.md:81-82`: entering the dungeon in slot 5 of the saved game's table crashes the process (exit -11); an open bug, "not looked into".
16. `docs/notes/controller.md` ("Not verified") and `docs/notes/steamdeck.md` ("Not verified"): no real controller, no real Deck, no Steam client has run any of the pad code or the layout; every statement about feel, the dead zone and the Steam layout is from pushed events and an X server.
17. The two README tables ("Where things stand") and `docs/notes/steamdeck.md` agree that the iPad and the Deck are untried on hardware; if either gets a first report, the README table, the release text in `release.yml` and `README.release.txt` (which says the Deck's on-screen keyboard "has not been tried on a real Deck yet") need the same edit.
